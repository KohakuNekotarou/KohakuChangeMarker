## 1. これは何か

- **BK-01** ★★★**ブック比較が答えるのは「どの章が、どの種類の変更で変わったか」までで、「どこが変わったか」は答えない。**
  章（＝ブックに並んだ1つのドキュメント）ごとに、**3つのモードそれぞれについて**変わった／変わらないの1ビットを出す
  （＝1章あたり3ビット）。作者の指定＝「ドキュメント単位で、変更あり／なしだけ見せる」「1つ見つかったらその章は終わり、次へ進む」
  ＋2026-09-10「**それぞれ1つでもひかかると、それぞれのモードで変わっていると判定**」。
  ⚠**「どこが」＝ページや語の位置は今も答えない**（それは行の右クリックから始まる文書比較の仕事＝BK-57）。
  - 訂正: ✅2026-09-10 対応（**コードを変更**）→ 1ビット→3ビット。**「1つ見つかったら終わり」はモードの中では生きている**
    （BK-29）が、**モードとモードの間には無い**（BK-74）

- **BK-02** ★★★**比較モード（Pixel / Story / Resources）とは無関係で、常に3モードとも走る。**
  パネルでどのモードを選んでいても、ブック比較は**画素・本文・定義の3つを毎回全部**調べる。
  ⇒ **モードを切り替えてから実行しても結果は変わらない。**
  ★**この核（モードの切替がブック比較の結果を変えない）は 2026-09-08 の作者確認そのまま**
  ⇒ **「選ばれているモードに従わせては」と再提案しない。**
  ⚠**ただし行の右クリックから始まる比較は別**＝あちらは選ばれているモードに従う（BK-57）。
  ⇒ **一覧は3モードで「変わった」と言い、そこから始まる比較は1モードだけ**という非対称は残っている。
  - 訂正: ✅2026-09-08 確認 → 規則はそのままで、作者の決定として★を1つ上げた。BK-57 との非対称も書き足した
  - 訂正: ✅2026-09-10 対応（**コードを変更**）→ **「常に画素」→「常に3モードとも」**。
    ★**決定を覆したのではなく広げた**＝「選ばれているモードに従わない」という核は変わっていない

- **BK-03** ★★★**文書比較（Start）とは完全に別の仕組み。** 指名（Target/Source）を変えず、比較を始めも止めもせず、
  マークも作らない。⇒ **比較中でもブック比較を実行できる**し、実行しても画面のマークは消えない。
  - 訂正:

- **BK-04** ⚠**ただし1つだけ道具を共有している** ―― ノンブルの位置を覚えておく表を、ブック比較は
  **測り直しながら**使う。章を1つ閉じるたびにその表は空になるので、**次に文書比較を始めたときは
  自分で測り直す**（結果は変わらないが、その1回だけ余分に測る）。
  - 訂正:

  ⇒ **章を改名しても組はずれない**が、**途中に1章挿入すると、それ以降が全部ずれる。**
  - 訂正:

- **BK-18** 章の数が違うときは、多い方の余りが**そのまま答えになる** ―― Target にだけあれば

  - 訂正:

  - 訂正:

## 5. 1つの章をどう判定するか

- **BK-22** ★★★**章は1組ずつ開いて、判定して、閉じる。** 全部先に開くことはしない。
  ⇒ **同時に開いている章は多くても2つ**（閉じられなかった章を除く）。
  - 訂正:

- **BK-23** ★★**既に開いている章は、開いたままの状態で使い、こちらでは閉じない。**
  人が開いたものを閉じるのは驚かせるだけなので。
  - 訂正:

- **BK-24** ⚠★★★**「開いたままの状態」には、まだ保存していない編集も含まれる。**
  画面に出ている章は**画面のとおりに**比べられ、相手はディスクから読まれる。
  ⇒ **メモリの中にしかない編集で「変更あり」と出ることがある。**
  これは「いまこの章は相手と違うか」への正しい答えで、「ディスク上の2冊は違うか」への答えではない。
  **どちらを聞きたいかは実装からは分からない**ので、揃えたいなら**先に保存する**。
  - 訂正:

- **BK-25** ★**比較のために開く章は、窓を作らず、ダイアログも抑える。**
  ⇒ フォント欠落やリンク切れの警告で止まらない。★**本体のブック用の「開く」は使っていない**
  （あれは UI を抑えられないので、警告を出す章がそのまま失敗になり、章ごと結果から消える）。
  - 訂正:

- **BK-26** ★★**開けなかった理由は、ブック自身に聞く。** `missing` / `out of date` / `in use` / `open` の4語。
  ⇒ 「削除された」「他の人が開いている」「新しい版で保存された」を**同じ言葉にしない。**
  ★**聞くのは失敗したときだけ**なので、全部開ける実行には一切の負担がない。
  ★ブックが何も言わないときだけ `could not open` と出る。
  - 訂正:

- **BK-27** ★★**開いた直後の章は、組版が終わっていないので、必ず組み終えてから画素を読む。**
  ⇒ これをしないと**中身が同じ2章が違って見える。** ★文書比較（Start）がこれを要らないのは、
  あちらが「人が画面に開いている文書」しか読まないから。
  - 訂正:

- **BK-28** ★★**章を汚さない。** 組版もラスタ化も文書に触るので、**入る前が汚れていなければ、出た後も汚れていない**
  ように戻す。⇒ **「保存しますか」と聞かれずに閉じられる**（UI を抑えて閉じるので、聞かれたら中身が黙って失われる）。
  - 訂正:

- **BK-29** ★★★**Pixel の判定は3段階で、どの段階でも早く終わる:**
  ①**ページ数が違えば、それだけで Pixel は変更あり**（1ページもラスタ化しない）
  ②ページの中は**最初の1画素が違った時点で**そのページの答え
  ③**最初に違ったページで、画素の走査は終わり**（残りのページは読まない）
  ⇒ **最後まで読まれるのは「画素が変わっていない章」だけ。**
  ⚠★★**この早期打ち切りは Pixel の中の話で、モードとモードの間には無い**（BK-74）。
  Story と Resources にも同じ形の打ち切りがある（差分が1件出たらそこで終わり）。
  - 訂正: ✅2026-09-10 対応（**規則文を書き換え**）→ 「章が終わり」→「画素の走査が終わり」。
    3モードになって「章の答え」と「モードの答え」が別物になったため

- **BK-30** ★**ページも並び順で対応する**（1ページ目と1ページ目……）。
  - 訂正:

- **BK-31** ★★**ラスタ化の条件は文書比較とまったく同じ**（144dpi・CMYK・アンチエイリアスなし・
  小さい文字も字形を描く・**非印刷指定のものは描かない**）。
  ⇒ 印刷されないもの（作業メモ・刷版への指示）を動かしただけでは変更にならない。
  - 訂正:

- **BK-32** ★★★**ノンブル（自動ページ番号）の場所は、常に比較から外す。**
  文書比較にはこれを外すかどうかのトグルがあるが、**ブック比較にトグルは無く、必ず外す。**
  理由＝**章を1つ入れると、それ以降のノンブルが全部ずれる**ので、外さなければ以降のページが丸ごと変更扱いになる。
  ★**「ノンブルとは何か」を判定する部分は文書比較と共有**しているので、2つの答えが食い違うことはない。
  - 訂正:

- **BK-33** ★**ページを比べられなかったとき**（大きさが違う・画素が取れない）**は Failed で、理由は「page 7」のように
  ページ番号だけ。** 「変更なし」には決してしない。
  - 訂正:

- **BK-34** ★**この実行が開いた章だけを、判定の直後に閉じる。** 閉じられなかったものは
  要約行の **left open** に数える ―― 窓が無いまま `.indd` を掴み続けるので、人が閉じる手段がないため。
  ⚠**「閉じ始められた」までしか分からない**ので、この数は**少なく出ることはあっても多くは出ない**。
  - 訂正:

## 5b. 3つのモード（2026-09-10 新設）

- **BK-74** ★★★**1つの章を Pixel → Story → Resources の順に3回判定する。章の組を開くのは1回だけ。**
  ブックを3周しない ―― 章を開いて組版するのが一番高いので（BK-35）、開いている間に3つとも済ませる。
  ⚠★★**モードとモードの間に早期打ち切りは無い**＝画素が既に違っていても、残る2つを必ず調べる。
  **Change 欄が「変わったモードを全部」名指しするための代償**で、これは仕様。
  ⇒ **章あたりのコストは Resources のぶんだけ必ず増える**（実測＝1ページの章5つで **2,421ms＝1章あたり約480ms**。
  Pixel だけだった頃の記録は「小さい章でも1章 0.2 秒ほど」＝BK-35 なので、**およそ2.4倍**）。
  - 訂正:

- **BK-75** ★★★**あるモードが判定できなかったときは、そのモード名に `?` を付けて Change 欄に出す。**
  「調べたが変わっていなかった」と「調べられなかった」を同じ見え方にしないため
  （BK-38 が章の単位で守っている規則を、モードの単位へ下ろしたもの）。
  **章の答えはこの順に決まる**:
  ①**1つでも変更あり → Changed**（他のモードが落ちていても、見つけた差は本物）
  ②**変更ゼロで中断 → NotCompared**
  ③**変更ゼロで、落ちたモードがある → Failed**
  ④**3モードとも走って変更ゼロ → NoChange**
  ⚠**②が③より先**＝中断で止まったモードは「失敗」ではない。
  ⚠★★**そして、中断で止まったモードは Change 欄に出さない**（`?` も付かない）。
  `?` は「調べようとして、できなかった」の印なので、**人が自分で止めたものに付けると、壊れた章を探させる**。
  ⇒ **中断した章の Change 欄は空**＝BK-46 の「何も見ていないなら何も書かない」と同じ答えになる。
  ★**理由（`fWhy`）は最初に落ちたモードの分だけ**＝あの欄はファイル名と並んで約38文字しかない（BK-47）。
  **どのモードが落ちたかは Change 欄の `?` が全部名指しする**ので、理由が1つでも情報は失われない。
  - 訂正: ✅2026-09-10 対応（**コードを変更**）→ 中断で止まったモードを記録しないようにした。
    それまでは Pixel の走査中に中断すると `Pixel?` が出て、理由欄に `Pixel: cancelled` まで残っていた
    （＝BK-46 の「空」と食い違っていた）

- **BK-76** ★★**Story の判定はストーリーの変更カウンターだけを見る**（本文の差分は走らせない）。
  章の答えは1ビットなので、それで足りる。⇒ **組版もしないので、ほぼ無料。**
  ⚠★★**そのぶんパネルの Story Edits 一覧より広く拾う**＝書体や色だけを変えた章も「Story ＝変更あり」になる。
  一覧のほうは本文の差分まで走らせて「言葉が同じ行」を落としているため。**別の問いに答えている**ので不整合ではない。
  - 訂正:

- **BK-77** ⚠★★**Resources の答えは、章を人が開いているかどうかで変わることがある。**
  BK-24（開いている章は画面のとおりに比べる）と、**定義の書き出しがメモリ上の文書を撮る**性質の掛け算。
  **両方こちらで開けば対称なので出ない**が、**片方だけ人が開いていると出る。**
  ⇒ **揃えたいなら先に閉じる。** ★同じ原因で `Language` は 2026-09-09 に比較から外してある
  （作ったまま開いている文書は66言語、開き直すと1）。**別の名前で同じ症状が出たら、同じ原因の再発として読む。**
