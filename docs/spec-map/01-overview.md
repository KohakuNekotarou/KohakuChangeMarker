## 1. この製品は何をするか

- **OV-01** 新旧2つの InDesign 文書を比べ、変わった箇所に印を重ねて見せるパネル。
  - 訂正: ✅2026-09-05 対応 → **OV-01b を新設**

- **OV-01b** **Kohaku InDesign MCP と組み合わせると、同じ文書の「ある時点」と「今」を比べられる。**
  KIDMCP の「Start Task Now」がその瞬間の文書の複製を取り、続けて「Compare with Kohaku Change Marker」を押すと、
  その複製が Source、今の文書が Target になって比較が始まる。
  ⇒ **比べる相手は「別の文書」でなくてよい。**（KCM 側の受け口から見た規則は OV-30。）
  - 訂正:

- **OV-02** 比べる対象は常に**2つ**（Target と Source）。3つ以上を同時に比べることはできない。
  ⚠ただし**「2つの文書」とは限らない** ―― KIDMCP 連携では**同じ文書の「今」と「その複製」**が対になる（OV-01b）。
  - 訂正: ✅2026-09-05 対応 → 「文書2つ」を「常に2つ（文書とは限らない）」に直し、OV-01b へ繋げた

- **OV-03** ブック（`.indb`）の比較は**別の機能**で、単位が違う（文書のページではなく、章ごとに「変わった／変わらない」を出す）。
  - 訂正:

- **OV-04** 印は**描画のたびに重ねて描いているだけ**で、`.indd` の中には書き込まれない。
  KCM を外した人がその文書を開いても、印は最初から無かったように見える。
  - 訂正:

## 3. 文書を書き換えない

- **OV-14** 比較マーク・✓・登録（Added/Removed）・猫の手スタンプは、**すべてプラグイン自身が持っている**。
  文書には保存されない。
  - 訂正:

- **OV-15** **文書の中身を変えるコマンドを出す機能は「Hide Unchanged Spreads」ただ1つ**（スプレッドを隠す）。
  それ以外でプラグインが出すコマンドは、窓を開く・スプレッドを切り替える・ズームを変える、の表示だけ。
  - 訂正:

- **OV-16** ただし**読み取るだけでも組版は走る**（文字の位置を聞けば、古い組版は組み直される）。
  そのため「入る前が clean だったなら clean に戻す」形で囲ってある ―― 「dirty にしない」ではない。
  - 訂正:

- **OV-17** PDF 書き出しの**最中だけ**「このスプレッドには透明がある」という申告を立て、書き出しが終わると外す。
  ★**申告を立てる相手は、書き出しが引き渡してくる複製（クローン）のほう**で、
  **利用者の文書そのものには一度も触らない。**
  ⚠この申告は文書に保存される種類のデータなので、**もし元の文書に立てたまま利用者が保存すると `.indd` に焼き付き、
  KCM を持たない人が開いてもそのまま残る**。「書き出しの間だけ・複製に」という形はそれを避けるためにある。
  - 訂正: ✅2026-09-05 回答＋対応 → **そのとおり、クローンにだけ立てている。**
    地図がそれを落とし、元の文書に立てているように読める書き方だったので直した。
    （旧実装は実際に元の文書へ立てており、書き出し中に保存すると焼き付いた＝実測 `kcmTransparencyItemCount` が 4。）

## 4. 比較モードは2つ

- **OV-18** **Pixel Changes**（既定）と **Story Changes** の2つ。フライアウトで相互排他に選ぶ。
  - 訂正:

- **OV-19** Pixel はページをラスタ化して画素を比べ、**「このページは刷り上がりが違う」**と答える。
  - 訂正:

- **OV-20** Story は本文そのものを差分し、**「どの文字が、何から何に変わったか」**と答える。
  - 訂正:

- **OV-21** **2つの結果を同時に持つことはない。** モードを変えると比較し直す。
  （両方を抱えると「今画面に出ているのはどちらか」の答えが2つになるため。）
  - 訂正:

- **OV-22** 今どちらのモードかは**パネルのタブに出る**（`Kohaku Change Marker - Pixel` / `- Story`）。
  - 訂正:

- **OV-23** モードの選択は**フライアウトの「Save Panel Settings」を押したときに**保存される（自動保存ではない）。
  一度保存してあれば、次に InDesign を起動したときは**自動で**そのモードで始まる。
  ⇒ **保存は手動・復元は自動**という非対称。フライアウトの設定トグルはすべて同じ扱い。
  - 訂正: ✅2026-09-05 対応 → 「保存され」が自動保存に読める書き方だったので、手動／自動を分けて書いた

## 5. 用語と状態

- **OV-24** **Target** ＝ 新しいほうの文書、**Source** ＝ 古いほうの文書。
  - 訂正:

- **OV-25** **「armed（比較中）」＝ Start が走って、まだ Stop していない状態。**
  armed かどうかを画面で示すのは **ON / OFF アイコンだけ**。
  - 訂正: ✅2026-09-05 対応 → **ご指摘のとおり誤り。** 名前は armed でなくても出る。OV-25b に分けた

- **OV-25b** パネルの `Target:` `Source:` の**ラベルは常に出ている**。その後ろに付く**名前**は2つの状態から来る ――
  **比較中なら「今のマークを作った対」、比較していなければ「Set as で指名した対」**。
  どちらも無ければ**ラベルだけ**が残る。
  ⇒ ★**名前が出ていること自体は「比較中」を意味しない。**
  - 訂正:

- **OV-26** フライアウトの **Set as Target / Set as Source** で、比較する2文書を**始める前に指名できる**。
  指名しなかったほうは自動規則で決まる ―― **アクティブ（前面）文書＝Target**、
  **Target 以外で「最も早く開かれた」文書＝Source**。
  ⚠**「最後に開いた」ではない。** 開いた順（`IDocumentList` の順）で、スクリプトの `app.documents`
  （最近使った順）とは並びが違うので、DOM を見て立てた予想は外れる（2026-08-31 実測）。
  - 訂正: ✅2026-09-05 回答＋対応 → **一番最後ではなく、一番最初に開いた文書。** どれが選ばれるかを書いていなかったので明記した

- **OV-26b** **比較中は Set as Target / Set as Source が灰色になる**（押せるのは「比較していない」かつ
  「アクティブ文書がある」ときだけ）。⇒ **指名を変えられるのは比較していない間だけ。**
  - 訂正:

- **OV-27** ★**Stop しても、指名した Target/Source の対は残る。**
  Stop が終わらせるのは比較であって選択ではない（start → stop → 直す → 同じ対でまた start、が想定している使い方）。
  ⚠**残るのは「Set as で指名した」対だけ。** 指名せず自動規則で始めた場合は指名そのものが無いので、
  Stop するとパネルの名前は消える（OV-25b）。
  - 訂正: ✅2026-09-05 回答 → **観察のとおり。** 指名していないときは消える、を本文に書き足した。
    要望のほうは **OV-27b** へ（未実装）

- **OV-27b** ⬜**未実装の要望**（2026-09-05）＝**指名した Target/Source を白紙に戻すフライアウト項目が欲しい。**
  ★中身の関数は既にある（`KCMClearChosenDocs`）が、**呼び手は model の Shutdown だけ**で、メニューからは呼べない。
  ⇒ フライアウトに項目を1つ足して繋ぐだけで実現できる。
  - 訂正:

- **OV-28** 指名が落ちるのは**その文書を閉じたとき**だけ。閉じた側だけが落ち、もう一方は残る。
  - 訂正:

- **OV-29** 比較を始められる条件は「**アクティブな文書があり、他に少なくとも1つ文書が開いている**」。
  満たさないとフライアウトの Start は灰色になる。
  - 訂正:

- **OV-30** **開いていない文書を Source にできる経路が1つある**（Kohaku InDesign MCP が貸す複製）。
  この経路は比較中でも**先に Stop してから**始め、Target と Source の両方を同時に指名する。
  自分自身のデータベースを Source に渡すことは拒否される。

## ⬜ この章で未確認

この章を書くにあたって**確かめていない**もの。「書いていない＝そういう決まりが無い」ではない。

- **スプレッド切替とズーム（表示を変えるコマンド）が文書を dirty にするかどうか**を測っていない。
  InDesign は最後に表示していたページとズームを文書に保存するので、dirty になっている可能性がある。
- **`SaveRestoreModifiedState` で囲っていない読み取り経路が2つある**（「測った上でわざと付けていない」と
  コードに書いてある）。その2つが何で、なぜ不要なのかを確かめていない。→ 第18章で扱う。
- **model だけを入れた状態が実機で本当に壊れないか**を測っていない（設計上の宣言としてはそうなっている）。
- **OV-17：同期書き出し（メインスレッド）でも複製が渡されるのか**を確かめていない。コードが「複製を渡される」と
  書いているのは `BeginExport` 一般についてで、同期の場合を名指しで測った記録は無い。→ 第11章で扱う。
- Exchange で公開されている版は **1.5.0**、手元は 2.1.0。**公開版と手元で振る舞いが違う項目**をこの章では区別していない。
