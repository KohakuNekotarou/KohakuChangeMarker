## 1. 何を光らせるか

- **SMK-01** ★★**Story モードは、変わった「文字そのもの」を光らせる。** ページに枠は描かない。
  ⇒ Pixel モードとは形が違う ―― あちらは**何が変わったか知らない**（画素が違う矩形しか分からない）ので
  枠を描くしかないが、Story モードは**どの文字か**を知っている。
  - 訂正:

- **SMK-02** ★**ズームで大きさが変わらない。** 文字に付いて描かれるので、拡大しても線が太くならない。
  ★**ページの外周に枠も出ない**（作者の指定）。
  - 訂正:

- **SMK-03** ★★★**文書は1バイトも変わらない。** 印は**文字の上に描いているだけ**で、
  文書に保存されず、組み直しも起こさない。⇒ 比較していない文書でも、保存しても、何も残らない。
  - 訂正:

- **SMK-04** ★★**縦組み・回転したフレーム・段抜きに、そのまま付いてくる。**
  座標を自分で計算していないため（**本体の文字エンジンが、文字を描くその瞬間に描かせている**）。
  - 訂正:

## 2. 見た目

- **SMK-05** ★**蛍光ペン**＝文字の**下**に敷く不透明な色地。色はマークの色（赤／シアン）に従う。
  - 訂正:

- **SMK-06** 濃さはパネルの「Marks opacity 25% / 75%」に従う（Pixel のマークと同じ設定）。
  - 訂正:

- **SMK-07** ⚠★★★**以前は「反転」だった**（下にあるものを白で反転させる。KBS と同じ見た目）。
  **紙と PDF に出せないので取りやめた。** 理由は2つあり、どちらも実測で分かった ――
  ①反転は**透明効果**なので、透明を保つ書き出しでは**描画ごと落ち**、平坦化する書き出しでは**塗りだけ残って反転が落ちる**
  ②仮にそれを解いても、**書き出したページは文字を最後に描く**ので、
  **地は反転して文字は反転しない**＝黒地に黒文字（実測：地 255→6・文字の芯 0→0）
  ⇒ **変わった語だけが読めないページ**ができた。
  ★**色地なら透明効果が要らない**ので、PDF 1.3 でも 1.4 でも、画面でも紙でも同じ絵になる。
  - 訂正:

## 3. 2種類のマークと、ぶつからない仕組み

- **SMK-08** ★★**マークは2種類ある。**
  ①**留まるマーク** ―― トグル（Always Show Marks on Target / Source）とツールのボタンで出る。消えない。
  ②**一瞬の印** ―― 一覧の行をクリックして飛んだときに出て、**約1秒で自分から消える**。
  - 訂正:

- **SMK-09** ★★★**同じ文書の中では、必ずどちらか片方しか使わない。**
  留まるマークがある文書では**留まるマークだけ**、無い文書でだけ**一瞬の印**が出る。**混ぜない。**
  ⇒ 2つが同じ文字を取り合うことが**構造上あり得ない**（後から調整しているのではなく、答えの形がそうなっている）。
  - 訂正:

- **SMK-10** ⚠この規則は**反転だった頃は「正しさ」だった** ―― 同じ場所を2度反転すると
  **元に戻ってしまい、両方が「ここを見て」と言った場所にだけ穴が空いた**。
  ★**いまは色地なので2度塗っても同じ色**。それでも規則は残してある（下の SMK-11 の理由）。
  - 訂正:

- **SMK-11** ★**重なりと隣接は1つにまとめる**（[0,5) と [5,9) は [0,9) に）。
  ⇒ 塗る回数が減り、継ぎ目も出ない。★**やめてはいけない** ―― 並べ替えと二分探索が
  「並んでいて重ならない」ことを前提にしている。
  - 訂正:

- **SMK-12** ⚠**光らせる範囲は毎回作り直す（覚えておかない）。**
  一覧は比較・再比較・行ごとの更新でいつでも作り直されるので、覚えていると
  **文字が動いた後も昔の場所を指し続ける**。★数千の編集でも整数が数千個ぶんの計算にしかならない。
  - 訂正:

## 4. いつ出るか

- **SMK-13** ★**トグル2つ**（Always Show Marks on Target / Source）＝**押していなくても出しておく**。
  Pixel モードで枠に対して働くのと同じ2つ（作者の要望「ボタンを押さなくても、両モードで出るように」）。
  - 訂正:

- **SMK-14** ★★★**ツールのボタンを押している間は「裏返る」**（足し算ではない）。
  カーソルの下の窓について、**出ていたものは消え、消えていたものは出る**。
  ⇒ ★これがこのプラグインのボタンの唯一の規則で、**だから「押している間だけ隠す」トグルを廃止できた**
  （2026-08-22。あれは「出しておいて、押している間だけ隠す」と言っており、前半は Always Show と同じだった）。
  - 訂正:

- **SMK-15** ★**ボタンを押すと、その窓の編集が全部いっぺんに光る**（1件ずつではない）。
  ⇒ Pixel モードで枠がいっぺんに出るのと同じ操作。
  - 訂正:

- **SMK-16** ★**一瞬の印は、両方の窓に出る。** 飛ぶ操作が両方の窓を動かしており、
  差分は**同じ編集が古い版のどこにあるか**も知っているため（第7章 ST-21）。
  - 訂正:

- **SMK-17** ⚠**時計を持っているのは一瞬の印だけ**。留まるマークに期限は無い。
  ★その時計は**このプラグインで2つしかない「時間で動くもの」の1つ**（もう1つはサムネイル）＝
  「タイマーは避ける」方針の意図的な例外で、理由は「**壁時計で消えなければならないから**」。
  - 訂正:

## 5. 紙と PDF

- **SMK-18** ★★**新しい版（Target）のマークは「Print comparison marks」が ON のときだけ出力される。**
  - 訂正:

- **SMK-19** ⚠★★**古い版（Source）は規則が違う** ―― **「Always Show Marks on Source」が ON なら出力される**。
  **印刷のトグルは見ない。**
  ⇒ 2つの文書で条件が非対称。第4章（Pixel のマーク）と同じ非対称。
  - 訂正:

- **SMK-20** ★**出力できるかは文書ごとに聞く。** 「どれか1つでも出せるか」で全体を止めることはあっても、
  **出せない文書のマークが紛れて出ることはない**。
  - 訂正:

## 6. どこに住んでいるか（なぜ model 側なのか）

- **SMK-21** ★★★**マークを描く仕組みも、何を光らせるか決める側も、両方 model プラグインにある。**
  理由は**書き出し**＝**PDF 書き出しはバックグラウンドで走り、UI プラグインには描画を一切渡さない**。
  ⇒ UI 側に置いていた頃は、**画面には出るのに紙と PDF には出なかった。**
  - 訂正:

- **SMK-22** ★決め手になる材料（トグル2つ・印刷トグル・比較の結果・どの2文書か）は**全部 model の持ち物**。
  UI から来るのは**ツールのボタンが押されているか**だけ。
  - 訂正:

## ⬜ この章で未確認

- **紙と PDF への出力**（SMK-18/19/20）は**コードから読んだだけで、実機で刷っても書き出してもいない**。
- **反転をやめた経緯**（SMK-07）の測定値は**当時の記録から引いたもの**で、この章を書くにあたって
  測り直してはいない。
- **ツールのボタンで「裏返る」**（SMK-14）は、Pixel モードでは何度も確かめているが、
  **Story モードでの実測はこの章では取っていない**。
- **一瞬の印が約1秒で消える**ことの実測（秒数そのもの）。
- **範囲の併合**（SMK-11）が実際に効いていること ―― 併合の有無で描画回数が変わるのを測ってはいない。
