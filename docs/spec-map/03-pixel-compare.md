# 03. Pixel 変更モード ― 何をどう比べるか

> コード地図での位置: **M3**（Pixel 比較エンジン ＝ 比較の本体と、1組のページを突き合わせる部分）・
> **M5**（ページデータ ＝ 登録と対応づけ）・M3 のノンブル検出。
> **画面に何が出るか**は第4章、**印刷や PDF にどう出るか**は第11章、**始め方と止め方**は第2章。
> 訂正の書き方は [00-index.md](00-index.md)。

---

## 1. このモードがしていること

- **CMP-01** Pixel 変更モードは、**2つの文書のページを1組ずつ絵にして、画素を突き合わせる**。
  文字を読むのでも、オブジェクトの一覧を比べるのでもない。
  ⇒ **何が変わったかは言えない**が、**見た目が変わったこと**は、変わり方によらず捉えられる。
  - 訂正:

- **CMP-02** ★**比べているのは「刷り上がり」**。非印刷に指定されたページアイテムは絵に描かれないので、
  それを動かしても変更にはならない。⚠**レイヤーの非印刷設定には効かない**（描画側がそう振る舞う）。
  - 訂正:

- **CMP-03** ★**2枚は必ず同じ条件で描く。** 片方だけ条件が違えば、文書の中のあらゆる縁が差として出る。
  ⇒ 描き方の設定（次節以降）は、すべて両方に同じ値が渡る。
  - 訂正:

## 2. どのページとどのページを比べるか

- **CMP-04** 通常のページは**並び順で対応づける**。両方の文書のページを先頭から順に組にしていく。
  - 訂正:

- **CMP-05** ★**「相手がいない」と登録されたページは、対応づけから外される**
  （Pages パネルの右クリック「Register as Added/Removed Pages」）。外したうえで残りを順に組にするので、
  **途中でページが増減しても、それ以降が1つずつずれることがない。**
  - 訂正:

- **CMP-06** 組の数は**少ないほうの文書に合わせて切り詰める**。あふれたページは「相手なし」として別に数える
  （画面にどう出るかは第4章）。⚠**あふれるのは長いほうの文書だけ**で、短いほうには生じない。
  - 訂正:

- **CMP-07** ★**マスターページは名前で対応づける**（`A-親ページ` どうし）。
  ⚠**通常ページと規則が違うのは意図的** ―― 位置で組にすると、片側にマスターが1つ増えただけで、
  それ以降が全部「無関係なマスターどうしの比較」になるため。
  名前が片方にしかないマスターは**比較されない**。組になったマスターのページ数が違えば、少ないほうに切り詰める。
  - 訂正:

- **CMP-08** ⚠**マスターページは登録できない**（メニューに出ない）。名前で対応づける以上、
  登録しても比較は何も変わらないので、**押せば何かが起きそうに見える項目を作らない**ため。
  - 訂正:

- **CMP-09** **隠れているスプレッドのページも比較される。** Hide Unchanged で隠れたものも、
  Pages パネルで隠したものも区別しない。
  ★**外さない理由は2つ。**
  ① **比較を始めるとき Hide Unchanged は必ず解除される**（CMP-25 の直前に走る）ので、
     そちらで隠れていたページは**比較の瞬間にはもう隠れていない**。
  ② **人が Pages パネルで隠したスプレッドを比較から外すと、片方の文書だけページ数が減り、
     それ以降の組が1つずつずれる。** 相手のいないページを外す仕組みは「登録」（CMP-05）のほうで、
     そちらは**どのページに相手がいないかを読み手が明示する**。隠す操作は表示の都合であって
     「相手がいない」という申告ではないので、同じ扱いにはできない。
  ⚠**出力では話が別**＝変更ページの書き出し（第15章）は隠れたページを**外す**
  ―― 画面にも PDF にも出ないページを名指ししても仕方がないため。
  ⇒ **「比較はする／出力からは外す」**という使い分けになっている。
  - 訂正: ✅2026-09-07 回答 → **KCM が選んで含めているのではなく、本体のページ一覧がそう答えている**
    （隠しスプレッドを選り分ける処理はどこにも無い）。そのうえで「外さないほうがよい理由」は
    上の①②で、規則文に書き足した。⚠**もし外すなら、両方の文書で同じスプレッドが隠れている保証が
    無いことが問題になる**（片側だけ隠れていると以降の対応づけが全部ずれる）ので、
    外すとしたら「隠れたページを登録と同じ扱いにする」という設計変更になる。ご希望なら別途提案します

## 3. 1組をどう比べるか

- **CMP-10** 1組のページを **144dpi・CMYK・不透明**で描き、その画素を突き合わせる。
  - 訂正:

- **CMP-11** ★**アンチエイリアスは切ってある。** 縁のにじみが消え、1画素に満たないずれが差として出なくなる。
  ⚠片方だけ入れると、文書の中のあらゆる縁が差になる。
  - 訂正:

- **CMP-12** ★**小さな文字も字の形のまま描く**（簡略表示＝グリークをしない）。
  簡略表示のままだと小さな文字は両方とも灰色の帯になり、**文字が変わっても差が出ない**。
  代償として、小さな文字の多いページは描くのに少し時間がかかる。
  - 訂正:

- **CMP-13** ★**配置画像は低解像度の代理で描く。** 原寸で描かせる設定は、**文書を変更済みにしてしまう**ため
  （CMP-29）。
  - 訂正:

- **CMP-14** 透明効果の品質は**最高のまま**。落とすと、影・ぼかし・混色の変化が検出できなくなる。
  - 訂正:

- **CMP-15** ⚠**ページの寸法が食い違う組は比べられない。** それは「変わらなかった」ではなく
  「**比べられなかった**」として数える（CMP-22）。
  - 訂正:

## 4. 違いをどう数えるか

- **CMP-16** 画素は **CMYK 4成分の差のうち最大のもの**で判定し、**差が 1 以上あれば「変わった画素」**。
  ★**RGB ではなく CMYK で比べるのは、RGB に直すと小さな差が丸められて消えるから**（読み手も CMYK の数値で考える）。
  - 訂正:

- **CMP-17** 変わった画素は、**記録用の粗いマス目（比較解像度の 1/4 ＝ 36dpi 相当）に集計される**。
  **1画素でも変わったマスは「変わったマス」**になる。
  - 訂正:

- **CMP-18** **変わったマスが1つでもあれば、そのページは「変わった」。** 1つも無ければ、そのページの記録は作られない
  ―― 記録が無いことが「変わらなかった」の表し方。
  - 訂正:

## 5. ノンブルを無視する

- **CMP-19** 「Ignore Page Number Marker」が ON のとき、**自動ページ番号を含む枠の矩形は比較から外れる**。
  新旧で番号が違うだけで全ページが「変わった」になるのを避けるため。
  - 訂正:

- **CMP-20** 除外する矩形は**両方のページから集め、両方に適用する**（同じ寸法のページであることを前提にしている）。
  - 訂正:

- **CMP-21** ★**比較のたびに測り直す**（前の結果を使い回さない）。
  ⇒ 画面に出る緑の網（除外された領域）は、**その比較が実際に使った矩形**を描く。
  - 訂正:

---

## 6. 何を報告するか

- **CMP-22** 終わるとステータス行が2行 ―― `marks start` ＋ `pages compared=N changed=M`。
  比べられなかったページがあれば `failed=K` が続く。
  - 訂正:

- **CMP-23** ⚠`compared=N` の N は**組にできたページの数**。登録で外したページと、あふれたページは入らない。
  ★**マスターページの組も入っている**（通常ページの組の後ろに続けて数える）。
  - 訂正:

- **CMP-24** ★**比べられなかったページを「変わらなかった」に混ぜない。** `failed=K` として別に数え、
  次に比べ直すときは必ず見直す（その組を記録に残さないので、次は「新しい組」として扱われる）。
  - 訂正:

---

## 7. 全部比べ直すか、変わったところだけか

- **CMP-25** ★既定は**全部**。前の結果を捨てて、組の全部を描き直す。
  - 訂正:

- **CMP-26** ★**「変わったところだけ」で済ませるのは、登録トグルを押したときだけ。**
  そのとき文書の中身は変わっておらず、**動いたのは対応づけだけ**なので、
  組が変わらなかったページは前の結果をそのまま使える（描き直さない）。
  - 訂正:

- **CMP-27** ⚠**Start と Ignore トグルは全部比べ直す** ―― 前者は中身が変わっているかもしれず、
  後者は除外する領域が変わるため。
  - 訂正:

- **CMP-28** 前回の対応づけが残っていない、比べている相手が違う、といった場合は
  **黙って「全部比べ直し」に落ちる**（食い違ったまま部分的に使い回すことはしない）。
  - 訂正:

## 8. 文書を汚さない

- **CMP-29** ★**入る前が未変更なら、出るときも未変更に戻す**（Target と Source の両方について）。
  絵にするだけでも組版が走ることがあり、組版は文書を変更済みにするため。
  ※第2章 RUN-24 と同じ約束を、比較する側から書いたもの。
  ⚠**この仕組みが効いていることは、まだ外から測れていない**（2026-09-07 夜に試みて失敗した。下記）。
  - 訂正: ✅2026-09-07 実施 → **止めた版を作って測ったが、この経路では測れないと分かった。**
    ★**いったん出した「ガードは仕事をしている」という結論は撤回する。**
    ①止めた版で、保存したばかりの2文書（どちらも `modified=false`）を比較したら**両方 `modified=true`** になった
    ―― ここで結論を出したのが誤りで、**対照を取っていなかった**。
    ②ガードを**戻した**版でも、同じ手順で**両方 `modified=true`** になった。
    ③さらに、**Start を一度も押さずに**開いたまま数回やり取りしただけで**両方 `modified=true`** になった。
    ⇒ ★★★**動いていたのは計器のほうで、原因は比較ではない**（スクリプトで開いた文書はひとりでに
    変更済みになる）。**第2章 RUN-24 が「この経路では測れない」と書いていたとおりだった。**
    ⇒ ★**測るには、人が手で開いた文書に KCM の操作だけをして、閉じるときに保存を聞かれるかを見る**しかない。
    ✅**コードは元どおりに戻してある**（2行は生きている。ビルド済み）。
    ⚠**同じ仕組みは他に13か所ある**（ブック比較・色抽出・overset 走査・peek・アドーンメント・
    Story 差分・Story ジャンプ）が、**そちらは1つも触っていない。**
