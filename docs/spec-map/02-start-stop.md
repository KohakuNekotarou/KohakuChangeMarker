## 1. 比較を始める入口は4つ

- **RUN-01** フライアウトの先頭にある **Start**。押すと比較が走り、走り終わると「比較中」になる。
  比較中はこの項目自体が **Stop** に変わる（項目は増えず、名前が入れ替わる）。
  - 訂正:

- **RUN-02** ブック比較の結果ダイアログで、**変わった章の行**を右クリックして出る **Start Change Marker**。
  その章の新旧2ファイルを窓で開き、そのまま比較を始める。
  - 訂正:

- **RUN-03** Kohaku InDesign MCP の **Compare with Kohaku Change Marker**（KCM 側のメニューではない）。
  開いていない複製を Source として貸してくる経路 ―― 第8節。
  - 訂正:

- **RUN-04** フライアウトの **Refresh Comparison** ―― いま比べている同じ2つを、もう一度比べ直す ―― 第7節。
  - 訂正:

- **RUN-05** ★**4つとも同じ手続きを通る。** 「比較を実行し、**成功したときだけ**比較中にする」という一続きの手順が
  1か所にあり、入口はそれぞれ「どの2つか」を決めて渡すだけ。
  ⇒ 入口ごとに始め方が食い違うことはない。
  ⚠**比較を「走らせる」経路は他に4つある**が、いずれも**すでに比較中のときだけ**動き、
  新しく比較中にすることはない ―― モードの切り替え・Ignore Page Number Marker の切り替え・
  ページの登録トグル・Load Check & Register。⇒ **比較を「始める」入口はこの4つで全部。**
  - 訂正: ✅2026-09-07 検算 → **規則は正しかった**。手続き本体を呼ぶ場所を全数で数えて**ちょうど 4 つ**
    （Start のトグル／2文書の入口（ブック章行）／貸し Source／Refresh）。
    ただし「比較を走らせるだけの経路が他にある」ことを書き落としていたので足した

## 2. どの2つを比べるか

- **RUN-06** 決め方は1つの規則で、**指名があればそれを使い、無ければ自動規則に落ちる**。
  Target と Source は別々に判断されるので、片方だけ指名する使い方も成り立つ。
  - 訂正:

- **RUN-07** 自動の **Target ＝ アクティブ（前面）文書**。
  - 訂正:

- **RUN-08** 自動の **Source ＝ Target ではない文書のうち、最も早く開かれたもの**。
  ⚠**「最後に開いた」ではない。** 文書の並びは開いた順で、スクリプトの `app.documents`（最近使った順）とは
  違うので、DOM を見て立てた予想は外れる（2026-08-31 実測）。
  - 訂正:

- **RUN-09** ⚠Target を指名したときも、自動の Source は「**Target ではない最初の文書**」であって
  「アクティブではない文書」ではない。★そうでないと、第3の文書を前面に出した瞬間に、
  指名した Target が自分自身を Source として渡されてしまう。
  - 訂正:

- **RUN-10** Start が押せるのは **Target と Source の両方が決まるとき**だけ。決まらない間、フライアウトの
  Start は灰色になる。
  - 訂正:

- **RUN-11** ★**「どの2つを比べるか」の解決だけは、灰色にする判断も押したときの実行も同じ規則を通る。**
  ⚠**ただし「メニューの見た目と押した結果が食い違わない」とまでは言えない** ――
  同じ文書どうしの拒否（RUN-12）は灰色の判断に**入っていない**ので、**押せるのに押すと断られる**場合がある。
  ★それは意図した設計で、理由は RUN-12 にある。
  - 訂正: ✅2026-09-07 検算＋訂正 → **半分は正しく、半分は言い過ぎだった。**
    解決子が1つなのは実測どおり（灰色の判断も実行も同じ関数を通る）。
    だが「食い違わない」は RUN-12 と矛盾するので削った（★第1章の教訓「【常に／だけ】と書いた箇所を疑う」が当たった）

- **RUN-12** **同じ文書どうしの比較は Start が断る。** ステータス行に
  `Target and Source are the same document. Bring another document to the front, or set one of them to another document.` と出て、比較は始まらない。
  ★**あえて灰色にしていない** ―― 灰色の項目は「今はできない」としか言わず、理由も直し方も伝えられないため。
  - 訂正:

- **RUN-13** ⚠この状態になる道は2つあり、直し方が違う。①同じ文書を Target にも Source にも指名した
  ②**Source だけ指名して、文書を切り替えずに Start した**（指名しなかった Target が、その同じ文書に解決される）。
  ★起きやすいのは②のほうで、そちらの直し方は「もう一方を前面に出す」。
  だからメッセージは両方の出口を名指ししている。
  - 訂正:

- **RUN-14** 自動規則だけでこの状態になることはない（自動の Source は Target を必ず除くため）。
  ⇒ 同じ文書の比較は、**指名したときにだけ**起こりうる。
  - 訂正:

## 3. Target と Source の指名

- **RUN-15** **Set as Target** / **Set as Source** は、**アクティブ（前面）文書**をそれぞれに指名する。
  比較を始める前に「どの2つか」を言っておくための項目。
  - 訂正:

- **RUN-16** 押せるのは「**比較していない**」かつ「**アクティブ文書がある**」とき。
  ★比較中に灰色なのは、走っている比較の足元で対が動くと、**パネルが名乗る文書と画面のマークの出どころが
  食い違う**ため。「選んでから始める」＝フライアウトでの並びの順。
  - 訂正:

- **RUN-17** 同じ文書を Target と Source の両方に指名することは**許している**（パネルに同じ名前が2行出るのは、
  指名したとおりの表示）。断るのは Start のほう（RUN-12）。
  - 訂正:

- **RUN-18** 指名しても比較は始まらない。ステータス行に `Target set.` / `Source set.` と出るだけ。
  ⚠**指名できなかったときは何も言わない**（アクティブ文書が無い場合。項目は灰色だが、メニューを開いたまま
  文書が閉じることはありうる）。
  - 訂正:

- **RUN-19** ★**Stop しても指名は残る。** Stop が終わらせるのは比較であって選択ではない
  （始める → 止める → 直す → 同じ対でまた始める、が想定している使い方）。
  - 訂正:

- **RUN-20** 指名が落ちるのは**その文書を閉じたとき**だけ。**閉じた側だけ**が落ち、もう一方は残る。
  - 訂正:

- **RUN-21** ★**Clear Target and Source** で、**走っている比較を止めてから**両方の指名を白紙に戻す。
  押せるのは「**比較中**」または「**どちらか一方でも指名されている**」とき
  ―― つまり**パネルの2行に消せるものが出ているとき**。
  ステータス行は、比較を止めたなら `Stopped, and Target and Source cleared.`、
  止めていないなら `Target and Source cleared.`。
  貸し Source（第8節）を持っていれば、それも一緒に忘れる。
  ⚠**Set as の2つとは門が違う**（RUN-16）―― あちらは「走っている比較の足元で対を動かさない」ために
  比較中は灰色。こちらは**比較ごと終わらせる**ので、その門が要らない。
  - 訂正: ✅2026-09-07 対応（**コードを変更**）→ 旧「比較中は灰色・比較は止まらない」を改め、
    比較中でも押せて、押すと Stop してから白紙に戻すようにした。第1章 OV-27b も直した。
    ⚠**実機未確認**（リンク未了）は章末に残してある

- **RUN-22** フライアウトでのこの一群の並びは
  **Start ／ Refresh Comparison ／ Set as Target ／ Set as Source ／ Clear Target and Source**。
  （Clear は、それが打ち消す2つの Set as の直下に置いてある。）
  - 訂正:

## 4. Start を押すと何が起きるか

- **RUN-23** 手順は ①比べる2文書の「透明の一覧」を点検し直す ②比較を実行する（Pixel はページをラスタ化して
  画素を比べ、Story は本文を差分する） ③**成功したときだけ**比較中にする ④Find Overset が ON なら
  Target を走査し直す ⑤パネルへ「作り直した」と通知する。
  - 訂正:

- **RUN-24** ★**文書を dirty にしない** ―― 入る前が未変更なら、出るときも未変更に戻す。
  読み取るだけでも組版は走る（文字の位置を聞けば古い組版は組み直される）ので、「触らない」ではなく
  「入る前の状態に戻す」という形になっている。
  - 訂正:

- **RUN-25** 比較の間、ステータス行に `Comparing changes...` と出る。
  - 訂正:

- **RUN-26** ★★**3秒たっても終わらなければ、Cancel 付きの進捗バーが出る。** 3秒以内に終わる比較では
  何も出ない。表題は Pixel が `Comparing pages...`（1ページなら `Comparing 1 page...`）、
  Story が `Comparing stories...`。
  ⚠**ブック比較のバーだけは最初から出る** ―― 章ごとに開いて組んで描くので、短時間で終わらないことが
  分かっているため。
  - 訂正:

- **RUN-27** ★**Start を Cancel すると、そこまでの結果を全部捨てて「比較していない」状態に戻る。**
  比較済みのページと未比較のページが混ざった画面 ―― 「変わっていない」と「まだ見ていない」の
  区別が付かない画面 ―― を作らないため。★Start はもともと比較していなかったので、押す前に戻るだけ。
  - 訂正:

- **RUN-28** ⚠**最後の1ページを終えた後には Cancel を見に行かない。** そこで押されたものを拾うと、
  すでに終わっている比較を丸ごと捨てることになるため。
  - 訂正:

- **RUN-29** Start は **Always Show Marks on Target / Source を触らない。** 触ると、保存してある
  パネル設定が比較のたびに上書きされ、保存する意味が無くなる。
  - 訂正:

- **RUN-30** 終わるとステータス行が2行で報告する。Pixel は `marks start` ＋
  `pages compared=N changed=M`（比較できなかったページがあれば `failed=K` が続く）。
  Story は `marks start` ＋ `stories changed=N edits=M`。
  ★**Story でページ数を言わないのは、1ページも比べていないから** ―― `pages compared=100 changed=0` は
  嘘ではないが「100ページを比べて差が無かった」と読めてしまう。
  - 訂正:

- **RUN-31** キャンセルしたときの報告は `comparison cancelled` ＋ `marks cleared` の2行。
  マークが消えた理由が画面に残るようにしてある。
  - 訂正:

- **RUN-32** 比較できなかったページ（ページサイズが食い違う、描画に失敗した等）は
  「変わらなかったページ」と一緒にしない。`failed=K` として数え、次に比べ直すときは必ず見直す。
  - 訂正:

## 5. 「比較中」という状態

- **RUN-33** **「比較中」＝ Start が成功して、まだ Stop していない状態。**
  ⚠比較が失敗した／キャンセルされたときは比較中にならない。
  - 訂正:

- **RUN-34** 比較中の対は**1組だけ**。別の対を比べるには先に止める必要があり、
  ブック行の Start（RUN-02）と KIDMCP 経路（RUN-03）は**自分で止めてから**始める。
  ⚠フライアウトの Start は、比較中なら Stop に変わっているので、そもそも重ねて始められない。
  - 訂正:

- **RUN-35** 比較中かどうかで変わるもの ―― フライアウト先頭の項目名（Start ⇄ Stop）／パネルのアイコン
  （ON / OFF）／パネルの `Target:` `Source:` に出る名前／Prev・Next ボタン／
  Hide Unchanged Spreads（比較中の Pixel モードでだけ押せる）／Export Changed Pages（比較中だけ）／
  Set as Target・Set as Source（比較中は灰色）／Refresh Comparison（比較中だけ）。
  ⚠**Clear Target and Source は比較中も押せる**（RUN-21）。
  - 訂正:

- **RUN-36** パネルの名前は、**比較中なら「今のマークを作った対」、比較していなければ「指名した対」**
  （第1章 OV-25b）。⇒ **名前が出ていること自体は「比較中」を意味しない。**
  - 訂正:

- **RUN-37** 名前は**フルパス**で出る。行に収まらなければ**前を省略**して末尾を残す（`...\new\ch01.indd`）。
  ⚠あふれた行では先頭の `Target: ` も一緒に切れるので、**上が Target・下が Source という並び**が
  その代わりを務める。
  - 訂正:

- **RUN-38** 貸し Source（第8節）は文書ではないので、**貸し手が付けた説明文がそのまま名前の位置に出る。**
  - 訂正:

## 6. Stop

- **RUN-39** Stop は**常に押せる** ―― 文書が1つも開いていなくても。
  マークを消して覗き（peek）を解くことは、どんな状態からでもできなければならない。
  - 訂正:

- **RUN-40** Stop で消えるもの ―― 比較マーク・旧版の画像・覗きの構え・スクロールバーの帯、そして
  **ページの登録（Added / Removed）**。
  ★登録が消えるのは、それが**比較の入力**（このページは相手なし、と比較に教える値）だから ――
  別の対で比較し直したときに古い登録が紛れ込まないようにしている。
  - 訂正:

- **RUN-41** Stop でも残るもの ―― **指名した対**（RUN-19）・**✓**・**猫の手スタンプ**・
  **貸し Source の登録**（RUN-52）。★✓ と猫の手は「読み手が残す印」で、比較の入力ではない。
  - 訂正:

- **RUN-42** Find Overset が ON のままなら、Stop の後にその走査結果を貼り直す。
  ⇒ 比較の帯だけが外れ、あふれの表示は残る。
  - 訂正:

- **RUN-43** Hide Unchanged Spreads は Stop で必ず解除される（隠れていたスプレッドが戻り、トグルも OFF）。
  ★マークが「変わっていない」の根拠なので、マークが消えたら隠す根拠も無くなる。
  ⇒ **「ONのまま灰色で戻せない」という手詰まりは起きない。**
  - 訂正:

- **RUN-44** ステータス行は `marks cleared`。
  - 訂正:

## 7. Refresh Comparison

- **RUN-45** いま比べている2つを**もう一度**比べ直す。片方を直した後に「**今**どうなっているか」を
  見るためのもの。これが無かった頃は Stop → Start の2回押しで、その間マークが画面から消えていた。
  - 訂正:

- **RUN-46** ★**Start の手続きそのものを、比較中の対に対して走らせている**（別の手順ではない）。
  ⇒ 「始める」と「比べ直す」が食い違うことはない。先に止める必要もない。
  - 訂正:

- **RUN-47** 押せるのは「**比較中**」かつ「**2つとも開いたまま**」のとき。それ以外では灰色。
  - 訂正:

- **RUN-48** ★★**必ず全部を比べ直す。** ページの登録トグルが使う「変わったところだけ」の再比較は使わない
  ―― 前回から**中身が変わっているかもしれない**というのが、この機能の存在理由そのものだから。
  - 訂正:

- **RUN-49** ⚠★**Refresh を Cancel すると、比較そのものが止まる**（Start の Cancel と違う）。
  Cancel を押せる時点でマークはすでに捨てられているので、そのままにすると
  **「メニューは Stop・パネルは2文書を名乗る・画面にマークは1つも無い」**という状態が残ってしまう。
  ステータス行は `refresh cancelled - comparison stopped`。
  - 訂正:

- **RUN-50** ⚠Pages パネルの右クリックにある **Refresh Page Comparison** は別物 ――
  選んだページだけを比べ直す・Pixel モードでだけ使える・**Cancel してもそこまでの更新は残す**。
  → 第3章。
  - 訂正:

## 8. 開いていない文書を Source にする（貸し Source）

- **RUN-51** Kohaku InDesign MCP が「タスク開始時の複製」を貸してくる。KCM はそれを**文書として開かないまま**
  Source にして比較できる。⇒ 比べる相手は「別の文書」でなくてよい（第1章 OV-01b）。
  - 訂正:

- **RUN-52** この経路は **先に Stop してから始め、Target と Source の両方を同時に指名する**
  （Set as Target ＋ Set as Source ＋ Start を1回で行うのと同じ）。
  ⇒ Stop してもパネルは2つを名乗り続け、フライアウトの Start はもう一度同じ複製と比べる。
  - 訂正:

- **RUN-53** ⚠**貸し手が複製ではなく Target 自身のデータベースを渡してきたら断る**
  （ステータス行 `Target and Source are the same database.`）。
  ★判定は「**同じファイルを指しているか**」ではなく「**同じデータベースか**」 ――
  複製は元と同じファイル名を名乗るので、ファイルで判定すると**正当な複製まで断ってしまう**。
  - 訂正:

- **RUN-54** 貸し Source の登録が続くのは、**指名されている間**か**比較中の間**か、
  **貸し手が返しに来るまで**の、いちばん遅いところまで。★**Stop では忘れない。**
  - 訂正:

- **RUN-55** Set as Source で実文書を指名すると、貸し Source の指名はそれに置き換わる。
  ⚠ただし**その複製から今まさに描いている最中**なら、登録だけは残る（貸し手が返しに来るまで）。
  - 訂正:

- **RUN-56** 貸し手が「これから消す」と告げてきたら、その複製で比較していれば止める。
  ステータス行は2通り ―― 比較していたなら `Stopped: the task-start copy used as Source was released.`、
  指名していただけなら `The task-start copy chosen as Source was released.`。
  - 訂正:

- **RUN-57** ⚠**KCM は複製を消さないし、「まだ在るか」を尋ねもしない**（尋ねても正しい答えが返らない）。
  返しに来るのは貸し手の義務で、KCM 側はそれを前提に組んである。
  - 訂正:

## 9. 文書を閉じたとき

- **RUN-58** 比較に関わる文書が**1つでも閉じたら、比較は丸ごと片づく**（Stop と同じ状態になる）。
  ★片方だけ生き残った状態 ―― 古いほうを閉じたのに、新しいほうにマークが残ったまま ―― は作らない。
  - 訂正:

- **RUN-59** 指名（RUN-15）は**1つずつ**判定され、**閉じた側だけ**が落ちる。
  ★対を「言っておく」ことの意味がそこにあるので、比較の後片づけとは扱いを変えてある。
  - 訂正:

- **RUN-60** ⚠閉じたという合図は「閉じた**後**」に届き、**どの文書が閉じたのかは教えてくれない。**
  ⇒ 追いかけているデータベースを、開いている文書の一覧と突き合わせて調べる。
  - 訂正:

- **RUN-61** ★アプリの終了中は、**記憶しているものを捨てるだけで画面には触らない**
  （窓とパネルが壊される順序は OS ごとに違い、その最中に触るのが終了時クラッシュの典型の形だから）。
  - 訂正:

- **RUN-62** ★★**バックグラウンドスレッドでは何もしない。** PDF の書き出しはバックグラウンドで走り、
  そこでは**すべての文書が複製として見える**ので、「一覧に無い＝閉じた」という判断が必ず外れる。
  ⚠実害があった ―― 非同期の PDF 書き出しが終わって複製が閉じたときに全部の片づけが走り、
  **マークが画面から消えた。**
  - 訂正:

- **RUN-63** Hide Unchanged Spreads だけは**閉じるときではなく保存のとき**に元へ戻す
  （隠したままの `.indd` を残さないため） → 第15章。
  - 訂正:
